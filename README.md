# EntityLink

Сервис поиска дубликатов контрагентов из разных источников. Сравнивает название,
адрес, телефон и идентификатор, объясняет предложение и позволяет вручную
объединить записи в группу, а затем отменить ошибочное объединение.

## Реализовано

Нормализация Unicode, регистра, пунктуации и российских телефонных номеров;
RapidFuzz для сходства названий и адресов; консервативный порог предложения.
Пустые поля не считаются совпадением. Разные непустые идентификаторы запрещают
объединение, включая конфликты внутри уже собранных групп.

Предложения не изменяют данные автоматически. Объединение сохраняет исходные
записи и журнал с предыдущей принадлежностью группам. Отмена выполняется в
обратном порядке зависимых слияний; повторная отмена безопасна. Записи источников
неизменяемы: повтор идентичных данных возвращает сохранённую запись, изменение
данных под прежним ключом возвращает 409.

Стек: Python 3.11+, FastAPI, PostgreSQL 17, psycopg, RapidFuzz, scikit-learn
для метрик на размеченных парах. `matching.py` содержит правила, `api.py` — API
и транзакции объединения, `db.py` — схему и подключение.

## Запуск

```sh
docker compose up --build -d
curl -H 'X-API-Key: local-demo-key' http://localhost:8089/health
python3 scripts/demo.py
```

Демо создаёт две записи, объединяет их и отменяет объединение. API и PostgreSQL
доступны только на localhost. Compose содержит демонстрационные пароль и ключ;
для внешнего развёртывания замените их и настройте TLS. Остановка:
`docker compose down`; том сохраняется.

## API

Все операции требуют заголовка `X-API-Key`. Схема запросов: `/docs`.

```sh
curl -X POST http://localhost:8089/entities \
  -H 'X-API-Key: local-demo-key' -H 'Content-Type: application/json' \
  -d '{"source":"crm","external_id":"42","name":"ООО Пример","tax_id":"1234567890"}'
curl -H 'X-API-Key: local-demo-key' http://localhost:8089/candidates
curl -H 'X-API-Key: local-demo-key' http://localhost:8089/entities
curl -H 'X-API-Key: local-demo-key' http://localhost:8089/merges
```

`POST /merges` принимает `{"left":"UUID","right":"UUID"}`; ответ содержит
идентификатор действия. `POST /merges/{id}/undo` отменяет действие.
Результат сравнения содержит `score`, `decision`, `reasons`. Оценка сходства
не является вероятностью совпадения. Ручное объединение разрешено и при низкой
оценке, но конфликт идентификаторов обойти нельзя.

## Проверки

Нужны `uv` и Docker:

```sh
cp .env.example .env
set -a
. ./.env
set +a
uv sync --frozen
docker compose up -d database
uv run ruff check .
uv run ruff format --check .
uv run pytest -q
uv run python -m scripts.evaluate
```

Тесты PostgreSQL используют временные изолированные схемы. Проверяются
нормализация, опечатки, недостаточность одного названия, конфликт идентификаторов
через промежуточную запись, повтор загрузки, журнал и порядок отмены.
CI повторяет линтер, форматирование и тесты с PostgreSQL.

`scripts/labeled_pairs.json` — небольшой размеченный синтетический набор с
опечатками, пропусками и одноимёнными организациями. Оценка показывает precision,
recall, F1 и номера ошибок. Это иллюстрация измерения качества, а не независимая
оценка точности на реальной базе. Набор не используется для обучения модели;
скоринг основан на явных правилах.

## Ограничения

Не более 500 записей: полный перебор пар имеет квадратичную сложность.
Мутации сериализованы блокировкой PostgreSQL, что упрощает безопасную отмену,
но ограничивает пропускную способность. Нет отдельного интерфейса оператора,
ролей пользователей и внешнего справочника адресов. Идентификатор проверяется
по форме (10 или 12 цифр), без проверки контрольной суммы и юридической истины.
Общий телефон не доказывает совпадение организаций. Для реального применения
нужны независимая разметка, настройка порогов и аудит операторов.
